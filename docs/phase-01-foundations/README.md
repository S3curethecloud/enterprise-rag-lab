# Phase 1 — RAG Foundations + Development Environment

## Goal

Understand the RAG architecture before implementing retrieval infrastructure.

## Learning Objectives

By the end of this phase, you should be able to explain:

- what RAG is;
- why RAG exists;
- retrieval versus generation;
- semantic search versus RAG;
- the basic RAG data flow;
- the Secure RAG trust boundaries;
- why authorization occurs before model access;
- the role future components will play.

You will also establish a reproducible Python development environment.

## Learning Sequence

1. What is RAG?
2. RAG vs semantic search
3. RAG data flow
4. Secure RAG mental model
5. Development environment
6. Environment verification
7. Knowledge checkpoint

## Phase Exit Criteria

Phase 1 is complete only when:

- [ ] The student can explain RAG without referencing ChromaDB or OpenAI.
- [ ] The student can distinguish retrieval from generation.
- [ ] The student can distinguish semantic relevance from authorization.
- [ ] Python virtual environment exists.
- [ ] `uv` works.
- [ ] Project dependencies are reproducible.
- [ ] Environment tests pass.
- [ ] Git working tree contains only intentional changes.

Do not proceed to Phase 2 until all exit criteria are satisfied.
